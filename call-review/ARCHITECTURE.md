# call-review 아키텍처

## 제품 원칙

- 학습 엔진보다 통화 경험이 먼저 보인다.
- 복습 구간만 정오답을 판정하고 자유대화는 통화 후 피드백한다.
- 음성 인식 결과는 확인 전까지 시도 횟수에 포함하지 않는다.
- 음성, 자막, 텍스트 입력은 같은 학습 턴을 공유한다.
- 자유대화 질문은 반드시 당일 복습 표현을 근거로 생성한다.
- 자유대화는 첫 질문과 최대 두 번의 후속 질문으로 제한한다.
- 학습자가 종료 의사를 보이거나 일정 시간 응답하지 않으면 즉시 종료한다.
- 원본 음성은 기본 저장하지 않고 필요한 경우에만 별도 동의를 받는다.

## 런타임 구성

모바일 화면 컴포넌트는 렌더링에 집중하고, 통화 단계 전환·무응답 타이머·답변 제출은 `apps/mobile/src/useCallSession.ts`에서 관리한다. 계획·리포트·일정·학습이력은 `CallReviewRepository`를 통해 로드한다. 이후 실제 학습 API 구현으로 저장소만 교체하고, STT는 세션 계층의 입력 경계에 연결한다.

```text
학습 데이터 API
      ↓
LearningHistoryItem 정규화
      ↓
buildCallPlanFromLearningItems
      ↓
모바일 통화 상태 머신
  ├─ 음성 입력 → STT → 인식 결과 확인
  ├─ 텍스트 입력 → 답안 제출
  ├─ 복습 턴 → 결정론적 판정
  └─ 자유대화 → 표현 기반 질문 → 최대 2회 후속 질문
                    ├─ 음성·텍스트 답변
                    ├─ 화면 선택 답변
                    └─ 종료 의도·무응답 감지
      ↓
CallReport 저장
      ↓
교사용 웹 관리 페이지
```

## 통화 상태

- `home`: 다음 전화와 오늘의 학습 요약
- `incoming`: 앱 내부 전화 수신 화면
- `connecting`: 마이크와 통화 준비
- `review`: 취약 단어·문장 복습
- `free-talk`: 오늘 표현을 활용한 짧은 대화(3번). 첫 질문에서 AI가 대화하기 좋은 표현 하나를 소재로 고르고(`topic`), 두 번째·세 번째 질문은 그 소재와 학생의 앞 대답에 이어지는 후속 질문만 한다(예: "Do you like movies?" → "Yes" → "What's your favorite movie?"). AI가 실패하면 묻는 문장을 소재로 고른 템플릿 질문을 쓴다. 짧은 대화에서는 음성 인식 결과 확인 단계 없이 바로 대답으로 처리하고 다음 질문으로 넘어간다(복습 문항만 확인 단계가 있다). 통화 결과를 저장할 때 서버가 대화를 보고 한국어 피드백 두 문장을 만들어 `talkFeedback`으로 함께 저장하고, 학생 앱 결과 화면·지난 리포트와 교사 리포트에 같은 글을 보여 준다.
- `complete`: 결과, 보상, 다음 일정

### 프리뷰 무응답 타이머와 화면 테마

짧은 대화의 20초 무응답 카운트는 새 질문이 화면에 표시된 뒤 1.5초의 읽기 여유를 주고 시작한다. 음성 입력·인식 결과 확인 중에는 세지 않으며, 텍스트 입력 또는 답변 선택지 조작이 발생하면 새로 시작한다. 잔여 10초부터 부드러운 안내를 표시한다. 실제 TTS가 연결되면 고정된 1.5초 대신 **질문 음성 재생 완료 이벤트**를 시작 시점으로 삼아야 한다.

밝은 화면이 기본이며 다크 모드 전환은 홈·마이페이지·수신·연결·통화·결과 전체에 적용한다. 현재 설정은 앱 실행 중에만 유지되는 프리뷰 상태다. 출시 전에는 기기 저장소에 선택값을 보존해야 한다.

복습 화면의 정답/다시 해보기 카드는 현재 프리뷰에서 영문 대소문자·구두점·공백을 정규화해 비교한다. 관사·축약형·유사 표현 허용 범위는 아직 정하지 않았으므로 실제 학습 판정 규칙으로 사용하면 안 된다. 짧은 대화에는 이 정오답 판정을 적용하지 않는다.

결과 화면은 세션이 기록한 표현별 첫 판정을 그대로 보여준다. 처음에 틀린 표현은 다시 맞혀도 `다시 보기`로 남고, 판정 전에 통화가 끝난 표현은 `못 했어요`로 표시한다. 같은 판정을 통화 결과로 저장한다.

### 통화 결과 저장

통화가 `complete`가 되는 순간 앱이 `POST /api/call-review/reports`로 결과를 한 번 보낸다. 본문에는 통화마다 새로 만든 `reportId`, 시작·종료 시각, 종료 사유, 표현별 판정(`correct`·`retry`·`skipped`, 틀린 경우 첫 답), 대화 질문과 답이 들어간다. 학생 번호와 이름은 본문이 아니라 Bearer 토큰에서 채우고, 복습·다시 볼 표현 수는 서버가 판정에서 다시 계산한다. 저장 실패 시 결과 화면에서 같은 `reportId`로 다시 시도하며, 서버는 `{학생번호}_{reportId}` 문서를 `create`로만 써서 중복 저장하지 않는다.

저장소는 Firestore `callReports` 컬렉션이고 BFF가 `firebase-admin`으로만 접근한다(클라이언트 규칙은 전부 거부). 로컬은 `FIRESTORE_EMULATOR_HOST`가 있을 때 에뮬레이터에만 쓰고, 실제 Firestore는 `CALL_REVIEW_FIRESTORE=enabled`일 때만 쓴다. 둘 다 없으면 저장 API는 503을 돌려주고 앱은 저장 실패로 표시한다. 학생 앱 마이페이지의 지난 통화 기록은 `GET /api/call-review/reports`로 본인 결과만 읽고(최근 10건), 기록을 누르면 그날의 리포트(표현별 결과·내 답·베플리와 나눈 대화)를 다시 본다. 마이페이지 상단 "나의 학습현황"은 예전 AI 튜터 학습 리포트 구성(누적 지표 4칸 → 코치 한마디 → 성취도 변화 → 결과 분포 → 영역별 성취 → 다시 볼 표현(틀림) → 제대로 못한 표현(넘김))을 따르며, 점수 대신 복습 정답률로 최근 30건을 집계한다(`apps/mobile/src/learningStatus.ts`). 운영 배포 전에 `firestore.indexes.json`의 `callReports`(studentId, endedAt) 색인과 규칙을 배포해야 한다.

## 학습 데이터 변환

전화관리에서는 기존 웹 BFF의 단어·문장 오답만 `LearningHistoryItem`으로 정규화한 뒤 공통 패키지의 `buildCallPlanFromLearningItems`로 전달한다. 평가 결과는 조회하지 않는다. 변환기는 단어·문장을 우선 한 개씩 선택하고, 남는 자리는 원래 순서의 항목으로 채워 기본 3개 복습 타깃을 만든다. 실제 회원번호와 인증 토큰은 변환 계층에 전달하지 않고 인증된 저장소 구현 내부에서만 다룬다.

로그인 성공 시 BFF는 Study API 토큰과 별도로 학생·교사 식별정보를 HMAC 서명된 `httpOnly` 세션 쿠키에 저장한다. 모바일용 학습 데이터 엔드포인트는 클라이언트가 전달한 회원번호를 신뢰하지 않고 이 세션의 주체를 사용한다. 세션 서명 키가 설정되지 않은 환경에서는 전화관리 실데이터 엔드포인트를 활성화하지 않는다.

`GET /api/call-review/learning-items`는 서명 세션에서 학생 식별정보를 읽어 단어·문장 오답만 조회한다. 요청 쿼리에는 조회 기간만 허용하고 회원번호는 받지 않으며, 응답은 `private, no-store`로 캐시를 금지한다. 기존 웹 POC의 `/api/study/wrong-answers`와 조회·정규화 로직은 공통 서비스로 공유하되, 기존 웹 POC의 평가 조회 범위는 유지한다.

### 모바일 Bearer 토큰

네이티브 앱과 웹 프리뷰는 BFF와 출처(origin)가 달라 쿠키 세션을 쓰지 않는다. `POST /api/call-review/mobile/session`이 study-api 학생 로그인을 대행하고, 학생 식별정보와 study-api 토큰 쌍을 `CALL_REVIEW_SESSION_SECRET`에서 파생한 키로 AES-256-GCM 봉인한 Bearer 토큰을 돌려준다. 앱은 토큰 내용을 읽을 수 없으며 iOS/Android 보안 저장소(웹 프리뷰는 localStorage)에 보관한다. `GET /api/call-review/learning-items`는 Bearer 토큰이 있으면 그 주체로 조회하고, study-api 토큰이 만료되면 refresh 후 새 토큰을 `renewedToken`으로 돌려준다. `DELETE /api/call-review/mobile/session`은 study-api refresh 토큰을 무효화한다. 개발 환경 CORS는 `localhost` 전체를 허용하고, 운영에서는 `CALL_REVIEW_MOBILE_ORIGINS`로 허용 출처를 지정한다.

앱은 `EXPO_PUBLIC_CALL_REVIEW_API_BASE_URL`이 설정되면 로그인 후 실제 오답으로 통화를 구성하고, 없으면 샘플 데이터 프리뷰로 동작한다. 실제 오답은 한국어 뜻을 복습 표현으로 쓰고, 자유대화는 AI 질문 생성 전까지 `buildTemplateFreeTalk`의 표현별 결정론적 질문을 쓴다. 전화 일정 API가 없어 일정은 샘플을 쓰고, 지난 통화 기록은 저장 API 전까지 비워 둔다. 프리뷰의 음성 입력은 STT가 없어 정답 문장을 인식 결과로 채운다.

### 학습 API 선택과 교사 화면

로그인 응답의 소속은 `memberships` 배열로 읽는다(센터장만 평면 필드). 학생 오답은 BM에 따라 조회 API를 고른다. 숲·IGSE는 학원 학습 API(`/api/study/results/academy/range`), 교실·웰·우영은 Smart Befly를 쓰고, BM을 모르거나 두 종류에 모두 속하면 둘 다 조회한 뒤 같은 오답(영역+정답)을 하나로 합친다. 한쪽 API가 실패해도 다른 쪽 결과로 통화를 구성한다. 학생 BM은 로그인 시 모바일 토큰과 웹 세션에 함께 담는다.

교사 화면(`apps/teacher-web`)은 `/api/*`를 BFF로 넘겨(`CALL_REVIEW_BFF_URL`) 브라우저 입장에서 같은 origin을 쓴다. 교사는 기존 `/api/auth/login`(role `teacher`)으로 로그인하고, 토큰과 서명 세션은 httpOnly 쿠키로만 보관한다. `GET /api/call-review/teacher/students`는 study-api `/api/teacher/customers`로 담당 학생을 불러와 회원번호 기준으로 합치고, Firestore의 최근 통화 결과를 붙인다(무응답 종료는 `재통화 필요`). `GET /api/call-review/teacher/students/{회원번호}/reports`는 요청한 학생이 지금 이 교사의 담당인지 매번 study-api로 다시 확인하고, 담당이 아니면 404를 돌려준다. 학생 계정 세션으로는 교사 API에 접근할 수 없다(403). 전화 일정은 교사 화면의 학습자 리포트와 운영 설정에서 설정한다.

교사 화면은 기존 교사용 LMS에 들어갈 웹 페이지로, AI 튜터 학습 리포트의 구성(요약 지표·총평·추이·결과 분포·영역별 성취·재복습 목록·회차별 상세)을 관리 전화에 맞게 옮겼다. 관리 현황은 최근 14일 일별 통화(종료 유형별), 반 전체 복습 결과, 여러 학습자가 다시 본 표현 TOP 5를 보여준다(`classStats`, 서버 집계). 학습자 리포트는 통화 기록 최대 50건으로 정답률 추이·결과 분포·영역별 성취·종료 유형·다시 볼 표현을 화면에서 계산하고, 다음 통화에서 복습할 현재 오답을 study-api에서 함께 보여준다. 차트는 외부 라이브러리 없이 CSS·SVG로 그리며, 색만으로 구분하지 않도록 범례에 이름과 수치를 함께 쓴다.

### 전화 일정

study-api는 학습 데이터를 읽기만 하므로 전화 일정은 우리 서비스가 Firestore `callSchedules/{회원번호}`에 둔다(BFF 전용, 클라이언트 규칙은 거부). 일정 형식·계산은 `schedule.ts`, 읽기·쓰기는 `schedule-store.ts`에 모아 두어, 나중에 LMS 일정관리 페이지로 옮길 때 저장소만 바꾸면 되게 한다. 일정은 요일(월~일), 시각(HH:mm, 한국 시간), 사전 알림(0·5·10·20·30분), 쉬기 여부이며 주 횟수는 요일 수로 계산한다.

- 교사: `GET/PUT /api/call-review/teacher/students/{회원번호}/schedule`. 저장할 때마다 담당 학생인지 study-api로 다시 확인한다.
- 학생 앱: `GET /api/call-review/schedule`(Bearer). 다음 통화 시각과 "오늘/내일/10월 23일(목) 오후 7:30" 표시 문구를 서버가 KST로 계산해 준다.
- 교사 현황: 학생별 다음 통화를 보여주고, 가장 최근 예정 회차에서 1시간이 지나도록 통화 기록이 없으면 `부재중`으로 표시한다(일정을 그 회차 이후에 만들었으면 제외, 30분 일찍 받은 통화는 인정).
- 알림 1차(기기): 앱이 일정을 받을 때마다 기기 알림을 매주 반복으로 다시 예약한다(전화 시각 + 사전 알림). 교사가 바꾼 일정은 학생이 앱을 다음에 열 때 반영되며, 기기 시간대가 한국이라고 가정한다.
- 알림 2차(서버 푸시, FCM 직접): Android 앱은 FCM 기기 토큰(`google-services.json`, Firebase 앱 `com.yoonsaeng.aicallreview`)을 `POST /api/call-review/devices`로 등록하고(최대 5대, 로그아웃 때 해제), 서버가 받아 주면(`CALL_REVIEW_PUSH_DISPATCH=enabled`) 기기 자체 예약을 지워 중복을 막는다. iOS는 아직 기기 자체 알림을 쓴다(APNs 연결 후 추가). Cloud Scheduler가 5분마다 `POST /api/call-review/dispatch`(`CALL_REVIEW_CRON_SECRET` 인증)를 부르면 그 사이 도래한 전화·사전 알림을 firebase-admin으로 FCM에 바로 보내고(외부 Expo 푸시 서비스 없음), `callDispatches/{회원번호}_{종류}_{시각}`을 `create`로 남겨 같은 회차를 두 번 보내지 않는다. 더 이상 유효하지 않은 토큰은 지운다.
- 어느 방식이든 전화 알림을 누르거나 앱 사용 중 전화 시각이 되면 홈에서 수신 화면을 띄운다.

## 모바일 배포 방향

초기 버전은 Expo managed workflow로 Android/iOS를 동시에 검증한다. OS의 실제 전화 수신 UI나 백그라운드 통화가 필요해지는 시점에 개발 빌드와 네이티브 모듈을 도입한다. 앱 내부 수신 화면과 푸시 알림은 먼저 분리해 검증한다.

## 음성과 AI 대화

- 읽어 주기(TTS): 짧은 대화 질문은 화면에 뜨면 읽고, 다시 듣기 버튼으로 반복한다. 복습 단계의 다시 듣기는 한국어 표현을 읽는다. 앱은 `GET /api/call-review/tts`(Bearer)로 Gemini TTS가 만든 WAV를 받아 재생하고(`GEMINI_API_KEY`, `GEMINI_TTS_MODEL`, `GEMINI_TTS_VOICE`), 같은 문장은 서버 메모리에 잠깐 캐시한다. 설정이 없거나 8초 안에 재생을 시작하지 못하면 기기 음성(`expo-speech`)으로 읽는다. 전화가 오면(수신·연결 화면) 복습 문항과 첫 대화 질문 음성을 기기 캐시(`expo-file-system`)에 미리 받아 두어 문항이 뜨자마자 읽는다. 통화 화면 상단 스피커 버튼으로 자동 읽기(음성 가이드)를 끌 수 있고, 다시 듣기 버튼은 꺼져 있어도 읽는다. Gemini 3.8 TTS는 C2PA 청크가 붙은 완성 WAV를 주므로 서버는 그대로 전달한다(헤더를 다시 씌우면 끝에 잡음). 무응답 타이머는 읽기가 끝난 뒤(그리고 다음 질문을 만드는 동안이 아닐 때) 센다.
- 음성 인식(STT): 앱이 답변을 녹음(`expo-audio`; Android AAC, iOS 16kHz WAV, 웹 WebM)해 `POST /api/call-review/stt`(Bearer)로 보내면 BFF가 Azure Speech Fast Transcription(`AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`, en-US)으로 바꾼다. Azure 설정이 없으면 OpenAI 음성 인식(`OPENAI_STT_MODEL`, 기본 whisper-1)을 쓴다. 녹음은 변환에만 쓰고 저장하지 않는다. 결과는 바로 제출하지 않고 "이렇게 들었어"로 확인받는다. 마이크 권한이 없거나 8초 안에 준비되지 않으면 글자 입력으로 바꾼다. 프리뷰(서버 없음)에서는 정답 문장을 인식 결과로 채운다.
- AI 질문: `POST /api/call-review/free-talk`(Bearer)이 당일 복습 표현·지난 대화·회차만 받아 질문 하나를 만든다(학생 이름·번호는 보내지 않음). 첫 질문은 전화를 받을 때 미리 만들고, 후속 질문은 학생 답에 짧게 반응한 뒤 아직 쓰지 않은 표현으로 묻는다. 학생 답은 따옴표로 감싼 데이터로만 전달한다. 응답은 JSON 형식·영어 질문(물음표 포함)·선택지 2개 이상을 검증하고, 실패·8초 초과·검증 실패면 앱이 결정론적 템플릿 질문을 쓴다. 모델은 `CALL_REVIEW_FREE_TALK_MODEL`(없으면 `OPENAI_MODEL`).

## 자유대화 생성 규칙

질문 생성 모델에는 당일 복습 표현, 학습자 레벨, 허용 주제와 최대 턴 수만 전달한다. 응답은 `questionEn`, `questionMeaningKo`, `answerHint`, `choices`를 가진 구조화된 형식으로 받는다. 모델 호출이 실패하거나 안전 기준을 충족하지 못하면 표현별로 준비한 결정론적 질문 템플릿을 사용한다.

자유대화 화면은 `코코의 영어 질문 → 자연스러운 한국어 뜻 → 학습자의 영어 응답 안내` 순서로 표시한다. 한국어 뜻은 번역 과제가 아니라 질문 이해를 돕는 보조 정보이며, 해석 표시를 꺼도 코코의 영어 질문은 항상 유지한다.

자유대화 응답은 정오답으로 처리하지 않는다. 통화 후 사용한 표현과 의사소통 성공 여부만 요약해 다음 관리 계획에 반영한다.

## 일정 권한

초기 운영 정책은 담당 교사가 전화 요일, 시간, 주당 빈도와 사전 알림을 설정하는 방식이다. 학습자 앱은 설정된 일정을 읽기 전용으로 보여준다. 추후 운영 결과에 따라 교사가 허용한 범위 안에서 학습자가 시간을 변경하는 위임 모드를 추가할 수 있다.

## 교사용 웹

교사 LMS에는 새 관리 페이지의 URL을 링크로 연결한다. 인증 연동 전에는 별도 로그인을 유지하고, 이후 LMS의 SSO 또는 안전한 단기 토큰 방식으로 연결한다.

## 복습 문항 출제 규칙

`packages/shared`의 `selectCallItems`가 학생 앱과 교사 화면에서 같은 규칙으로 문항을 고른다. 후보는 study-api의 단어·문장 오답(최근 365일, 같은 표현을 여러 차시에서 틀렸다면 가장 최근 학습 시각)이고, 지난 통화 결과(`callReports`)와 비교한다.

1. 새 학습: 표현을 마지막으로 통화에서 연습한 뒤(또는 아직 연습한 적 없을 때) 학습 차시에서 또 틀린 표현. 지난 통화 이후 여러 차시를 학습했다면 모두 내되 최근 차시부터, 한 통화 최대 10문항. 남은 것은 다음 통화에서 이어서 낸다.
2. 새 학습이 없으면 복습 필요: 최근 통화 결과가 틀림(먼저)·넘김인 표현, 오래전에 연습한 것부터 최대 10문항.
3. 모두 맞혔다면 가장 오래전에 연습한 표현 3개를 돌아가며 다시 본다.

한 번에 맞힌 표현은 학생 앱·교사 화면 모두 "완료함"으로 표시한다. study-api 학습 시각은 시간대 없는 한국 시간이라 `kstToIso`로 바꿔 통화 시각(UTC)과 비교한다.
